# EA 原始码风控稽核

目的：确认 `tools/data/risk-matrix.json` 里的每一格，跟 EA 原始码的实际行为一致。

目前矩阵里的资料**全部来自各产品页文案**，没有一支经过原始码核对
（`verified` 皆为 `false`）。文案与程式码不一致是这类产品最贵的错误 ——
客户依文案配置资金，程式却不是那样跑。

---

## 稽核流程（每支 EA 一次）

把下面这段丢给 agent，`<EA>` 换成产品名，附上该支 EA 的 `.mq4` / `.mq5`：

```
请稽核这支 EA 的风控机制，只根据原始码回答，不要参考任何行销文案。

针对以下七项，逐项给出「有 / 无 / 有但有条件 / 结构上不适用」，
每一项都必须附上「档名:行号」与该行程式码，否则视为「无法确认」：

1. 单笔硬止损：每笔订单开仓时是否写入 SL？是伺服器端 SL 还是程式内部判断？
   若为内部判断，EA 停止运行时该保护是否失效？
2. 逆势加仓：是否存在往不利方向的加仓？手数是固定、递增还是倍数？
3. 层数硬上限：单边最大层数是否有「不可被参数绕过」的硬上限？
   请区分「参数预设值」与「程式内硬编码上限」—— 只有后者算硬上限。
4. 整批 / 全局止损：是否有整体浮亏上限？预设是开还是关？
5. 账户权益熔断：是否有帐户层级的停机机制？触发条件与门槛为何？
6. 点差 / 滑点过滤：进场前是否检查？超过阈值时的行为是什么？
7. 对冲 / 反手削单：是否存在？触发条件为何？

另外请特别指出：
- 任何「预设关闭」的保护机制（这是最容易被误解成有保护的情况）
- 任何可被使用者参数设成「无上限」的风险控制
- 单笔止损与整批保护之间是否存在覆盖不到的缺口

最后输出一段 JSON，格式与 tools/data/risk-matrix.json 的 cells 相同。
```

## 核对与回填

1. 把 agent 给的 JSON 与现有的 `risk-matrix.json` 逐格比对。
2. **有差异的格子先看程式码本人，不要直接采信 agent。** 每一格都有行号，很好验。
3. 确认无误后更新 `risk-matrix.json`，把该支 EA 的 `verified` 改成 `true`。
4. 重新生成并检查：

   ```
   python3 tools/gen_risk_matrix.py
   python3 tools/check_consistency.py
   ```

5. 若稽核结果与产品页文案冲突，**以程式码为准**，同步修正 `ea/<slug>.html` 的文案。
